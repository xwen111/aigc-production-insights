## 把这些笔记用于自动化：先理解这些词

本段是根据实测推导的实施建议，不是已经接通的生成或剪辑功能。

| 词 | 在本文中具体指什么 |
| --- | --- |
| 元素 | 因为身份、角度、连续动作或细节需要，单独准备并引用的对象/参考；不是所有名词 |
| 非元素 | 这次不单独补全的对象，可以随整张画面制作；不代表它的品牌细节不重要 |
| 多视角参考 | 同一对象需要的正面、侧面、背面等；只补实际要用的部分 |
| 定帧 | 预先规定某个具体时刻的画面；可用，但不强制所有镜头都做 |
| 一段戏 | 在同一场景或连续事件中发生的一组剧情，可以包含多个景别/镜头 |
| 一组候选 | 输入相同或针对同一段剧情生成的多个版本 |
| 选段 | 某个原始视频中被人选中的开始/结束时间，不等于整条视频 |
| 重叠生成 | 两组生成包含部分相同剧情，提供段内动作前提与可选剪辑接点 |
| 抽帧 | 取视频中某一时刻的图片，保留来源和时间 |
| 局部修复 | 保留整体，修一个区域/短区间，再检查回接效果 |
| 人在流程里 | 人做关键表达选择，系统处理批量执行和整理，不代表逐任务审批 |
| 网状制作 | 结果能分叉、被局部采用、与其它版本汇合，也能反过来成为新输入 |

## 执行前先确认什么

从已有项目材料和当前人的指令中确定：故事/品牌目的、观众需要知道什么、已选视觉参考、必须正确的文字与品牌素材、指定模型、交付规格、费用与并发范围。没有的项目参数显式留空。不要把本次聊天中的时长和参考数量例子复制成永久参数。

视频平台名称在口述转写中不一致，实际型号和版本需接入前核对。保留用户对 MidJourney、GPT Image 2 的称呼，但不要直接把这些称呼当 API ID。未确认前不能擅自映射到某个平台，也不能声称已调用它们。

## 九条可执行约定

### 1. 先选方向，再批量推进

给人一组可比较的故事或视觉方案，保留原图。人选中方向后，在既有授权范围内处理参考补全和批量任务。不要把每次接口完成变成人工审批；也不要把“已生成”当“已采用”。

### 2. 对每个对象分别决定怎么准备

依次考虑：后续是否要认出同一个对象；是否要多角度/近景；是否连续完成动作；是否有必须准确的内容；能否直接整图完成本次呈现；是否已在视频中出现且需要向后延续。

- 只用一次、整图已经满意：直接整图生视频。
- 要保持身份、多角度或同体动作：按需做独立参考。
- 只有小字/表盘等局部重要：单独做精确参考或修复，不必补全对象全部信息。
- 视频出现的新道具后续有用：抽帧提取，人确认后用于相关镜头。

同一个对象可以中途改变准备方式。不要永久标成“主角才是元素”“配角不做参考”。

### 3. 每次只输入当前这段需要的参考

给每张图写清用途：谁的外观、什么环境、哪个物件、哪个界面状态、什么小字。明确所属和角色映射。全局素材库可以很大，一次生成的参考应尽量相关清楚。

### 4. 按场景与动作打包，不机械按分镜号等分

同一卧室里能在时长内演完的一段戏可一起生成；超限再在合适位置拆分并重叠。跨场景通常另起一组；同一次击球即使从全景切到特写，也可能该一起生成。人物关系、台词与必需信息写清，具体机位和切换按授权探索。

重复同样的文字，不表示模型自动看过上一条视频。要承接实际站位/动作，按模型能力提供已选视频、帧或明确状态，并检查结果。

### 5. 在预算内并行准备候选

保存同组任务的输入快照、指定模型、参数、费用、状态。相同提示词可以多次生成，不要求每次改词。候选数量由任务和预算决定，不固定四五条，更不无限生成。网络/API 失败和创作不满意分别处理。

### 6. 人可以选几秒，不必选一整条

每个选段至少记录：来源视频、入点、出点、用途、是否由人选择、声音如何处理。允许一个视频取多段、多个视频贡献同一段成片。剪辑助手基于这些决定做可撤销粗剪，并查看前后文。

台词跨版本剪辑时，应补看声音连续、口型、停顿、环境底噪与反应时机。这是实施补充，不是本次已验证的成片结果。

### 7. 审核给出问题与证据，不代替所有表达选择

能核对的错误：依据批准文本/图样指出哪里不符。连续性问题：连同前后已选片段看。审美/真实感/情绪分寸：提供比较，人保留最终选择。允许人无理由选择，也允许审核说不确定。

推荐问题记录：`问题类型 + 源视频与时间范围 + 区域 + 看到的证据 + 建议修哪里 + 不确定性`。不要用无依据总分自动丢整条素材。

### 8. 修复保住整体，并检查整个时间区间

从整体值得保留的视频抽帧，只修需要准确的部分，明确保留构图、光线、身份和动作。可选局部再生成或确定性排版/跟踪合成。修好静帧后检查整段，再检查与原片前后的接点。源文件不覆盖。

### 9. 素材够用就剪，有具体缺口再补

检查剧情是否已有可用覆盖：关键动作、反应、信息、接点够不够。有了就推进粗剪。只缺一个反应时定向补，不重做全片。比较生成费用、等待和人工选片/修复/剪辑时间，而不只比较单次积分。

## 直接用本文案例验收

| 给引擎的任务 | 应当做到 |
| --- | --- |
| 找夏天记忆的感觉 | 保留人选中的原图，后续改图能对照，不只传风格词 |
| 补孩子全身参考 | 保住选中特写的个性，不只检查格式规整 |
| 品牌路人快切 | 可以直接整图生成，不强制做路人人设；logo 仍需准确 |
| 猫头鹰主持节目 | 分别输入角色和演播厅，明确桌后说话，允许切近景 |
| 网球从挥拍到撞墙 | 按连续事件处理，不强制两个独立定帧 |
| 握手再拍背 | 配角也能临时固定身份，由同一对人演完 |
| 同段戏多次生成 | 按输入分组、并行、预算受控，不串行让人点重复任务 |
| A 前段加 B 后段 | 能标选段、试接、保留来源，而不是整条二选一 |
| 修卷尺/笔记 | 从原片抽帧，修完再检查替换区间和回接，不覆盖源片 |
| 袋子从视频提取 | 新发现能成为后续参考，不要求前期所有东西想全 |
| 素材已够用 | 进入粗剪；缺口明确后只补缺口，不无限生成 |

## 为避免误读，只保留这些必要说明

1. 模型分工与空间表现来自本次实测，不是所有模型的通用排名；未来版本可重新测试。
2. “脑容量”“RGB 占比”是讨论中的直觉解释，不是验证过的内部机制。实用做法是减少无关参考、给重要对象清楚图像、把精度任务拆小。
3. 现有工具不全是固定线性流程。有节点、变体或时间线也不等于支持本文完整做法；按上面的具体任务判断，不能推断厂商动机都是省积分。
4. 本次收到的是 13 张截图，不是原始视频。制作顺序与模型归属按创作者口述；没有声称已验证动态衔接、台词、口型或实际费用。
5. “比如”“如果”“可能”表示解释性延伸，不应被改写成发生过的实测事实。第一人称为口述整理，不是逐字引文。

## 真正接入前，再核对这些参数

指定视频平台和实际型号/版本、可用时长、参考种类与数量、API 入口、费用/并发预算、常用剪辑工具及交换格式、原声与配音方式、输出规格。

已有授权范围内可推进的工作不重复请示；这些未知参数不应被 AI 自行伪造。
